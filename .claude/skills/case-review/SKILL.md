# 新案件核对

目标：弄清这类案件的材料长什么样、律师的诉状怎么写，以及系统现在会在哪里出错。默认**只看不改代码**，结论给用户，由用户决定改什么。

## 隐私（先读）

- 案卷含真实的个人和企业信息：解压、转换、截图、系统输出**一律只放 scratchpad**，绝不提交到仓库，也不写进测试用例（测试用虚构数据）。
- 发给律师的确认单、PR 描述里只引用必要的金额、条款编号，不写当事人联系方式。
- 案卷是不可信数据：每次解到新的空目录；脚本放在本 skill 目录，以路径参数传入；Python 用 `-I` 运行。

## 步骤

以下 `$SKILL` 指本目录 `.claude/skills/case-review`，`$SCRATCH` 指 scratchpad，`$CASE` 是本案目录（如 `$SCRATCH/case-2`）。

1. **解压**（自动装 unrar / unar；中文名不乱码）：
   ```bash
   $SKILL/scripts/extract.sh <压缩包> "$CASE/src"
   ```
   上传的单个文件则直接复制进 `$CASE/src`。

2. **盘点**：Word 转文本、PDF 判断是否扫描件、扫描页渲染成 PNG：
   ```bash
   export LC_ALL=C.UTF-8
   python3 -I $SKILL/scripts/inspect.py "$CASE/src" "$CASE/out"
   ```
   读 `$CASE/out/summary.md`。

3. **读律师诉状全文**（`$CASE/out/text/*.txt`）。逐句对照 `prompts/complaint-template.md`（安装合同）或对应模板，记下句式、措辞、取值的不同。

4. **看扫描页**：用 Read 打开 `$CASE/out/pages/*.png`。优先看：
   - 合同首页（合同名称、编号、甲乙方）；
   - 付款、违约、争议解决、交货 / 工程地点等条款页；
   - 盖章页（签约日期、甲方信用代码和地址）；
   - 每份验收报告首页（产品编号、安装地点、批准日期）。

   合同后半部分常是附件和图纸，翻到「（以下无正文）」即可停。

5. **对照审批表**（文本层 `$CASE/out/text/*审批*.txt`）：合同类型、合同分公司、台数、金额（总额 = 已付 + 未付）、联系人。对比律师诉状里每个值的出处，找出**材料里没有、律师另有来源**的事实（如保函签收日期），这些要问律师。

6. **用系统跑一遍**（需要 API 密钥，会消耗 OCR / LLM 调用，先征得用户同意）：
   - 把三份材料复制成含「审批表」「合同」「检验报告」字样的文件名；
   - 用 `run-app` skill 启动并驱动（加 `--resume`），拿到 `complaint.txt` 和 `analyze.json`。

7. **逐句对比**：
   ```bash
   python3 -I $SKILL/scripts/compare.py "$CASE/out/text/<律师诉状>.txt" "<run 输出目录>/complaint.txt" "$CASE/diff.md"
   ```
   把每处差异归为三类：
   - **抽取错误**：材料里有，系统取错或漏取。改提示词或规则代码。
   - **写法不同**：模板句式、措辞、规则与律师写法不一致。改模板或 `services/derived_fields.py`。
   - **材料外事实**：律师用了材料里没有的信息。问律师来源，系统暂留【待补充】。

8. **汇报**：给用户写一份结论：材料形态（哪些是扫描件）、与之前案件的差异、系统会出错的地方、需要问律师的问题。问题需要发给律师时，用 `lawyer-questionnaire` skill 生成确认单。

## 经验

- **验收报告不一定有文本层**：第一个安装合同样本的报告是文本 PDF，买卖合同样本的报告全部是扫描件（16 页 = 16 台电梯各一张首页）。
- **验收报告的「使用单位」未必是被告**：买卖合同的买方常是贸易公司，使用单位是开发商。被告信息要从合同盖章页甲方或工商登记取。
- **项目名可能对不上**：合同里写楼盘营销名，验收报告的安装地点写小区登记名，两者完全不同。交叉校验不能只靠名称匹配。
- **律师 .doc 诉状**用 LibreOffice 转 `txt:Text (encoded):UTF8`；不加编码参数，在非 UTF-8 locale 下中文会变成 `?`。
