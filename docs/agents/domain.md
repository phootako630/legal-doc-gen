# 领域文档

本项目采用 single-context 布局：根目录 `GLOSSARY.md`，架构决策存 `docs/adr/`。

## 探索代码前

- 若根目录 `GLOSSARY.md` 存在，先读它，采用其中的中文领域术语。
- 阅读 `docs/adr/` 中与当前工作有关的 ADR。
- 若未来出现 `GLOSSARY-MAP.md`，按其索引阅读相关领域的词汇表与 ADR。

这些文件尚不存在时继续工作，无需提前创建空文件。`domain-modeling` 在实际澄清术语或形成决策时创建、维护文档。

## 使用领域语言

需求、issue、设计讨论、测试名称使用词汇表定义的术语；中文法律术语为准，技术标识符保留原文。术语尚未定义时先判断是否已有等价词；存在歧义则交由 `domain-modeling` 澄清。

`GLOSSARY.md` 只记录领域词汇；实现与架构决策写入适当文档或 ADR。业务含义、证据保留与律师确认遵循 `CLAUDE.md` 的中文法律领域约定。

## 决策冲突

提议与现有 ADR 冲突时，说明 ADR 编号、冲突点和重新讨论的理由，再与用户处理分歧。
