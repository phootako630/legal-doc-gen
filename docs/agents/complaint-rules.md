# 起诉状生成与律师确认的填写规则

改派生字段（`services/derived_fields.py`）、起诉状模板与渲染、抽取守卫（`apply_rule_guards` 等）、原告信息表，或把律师确认单的答复落成规则时读本文件。这里的规则是律师确认的领域事实：改动须有律师答复为依据，条件、例外与确认单题号一并保留。

## 起诉状生成（④：模板填槽）

- 用带占位符的模板（`complaint-template.md`，按律师提供的诉状模板逐句对齐）做**确定性渲染**：后端 `complaint_renderer.py` 填槽，前端导出 Word。
- 标注规则由**代码**按字段 status 贴，稳定可控：
  - `value=null` → 正文写 `【待补充】`
  - 冲突字段 → `【高亮冲突：<值>】`
  - OCR/扫描来源 → `⚠️ 待核实：<值>`
  - 正常 → 直接写入
- 格式对齐律师模板：金额只写阿拉伯数字（模板自带 `¥…元`），日期 `2024年2月26日`（不补零）；已付 / 欠款默认写占合同款比例，二者之和不等于总价时写算式（见下）。
- 可选占位符（`complaint_renderer._OPTIONAL_KEYS`：违约条款引用、已付 / 欠款括注、违约金上限、质保期到期句、补充协议句）：规则判定不需要时值为空串，渲染为空、不算【待补充】、不计入就绪度。
- 导出 Word 保留黄色高亮：`/api/generate` 把每个填空值包在 `⟦…⟧` 里（`render_complaint(mark_fills=True)`），前端预览标浅黄、Word 导出转为黄色突出显示，供律师最后复核。

## 律师确认的填写规则

出自两份《起诉状规则确认单》，确定性代码实现于 `services/derived_fields.py`，律师改过的值不覆盖。

- 原告：买卖合同 = 总公司全称（`PLAINTIFF_HQ_NAME`），与合同盖章页乙方不一致时以乙方为准并标待核实；安装合同一律以合同盖章页「乙方 / 安装方 / 安装单位」（`contract_party_b`）为准，审批表「合同分公司」只作参考（确认单（五）第 1 题：有的诉讼由二、三级分公司提起，合同却是一级分公司签的）；合同乙方读不到时才按审批表推出（路径中第一个分公司拼总公司全称；路径里是独立工程 / 营销公司时原告就是该公司，按原告信息表补全称），标待核实。合同乙方不含总公司全称、原告信息表也查不到的（如验收报告上的施工单位）不当原告；第三行：分公司写「负责人」，总公司和独立公司写「法定代表人」；只有总公司在姓名后加职务（`PLAINTIFF_HQ_REP_TITLE`，「张三，董事长」），信息表已写了职务（「姓名，职务」「姓名、职务」「姓名（职务）」或空格后的常见职务名）的保留原写法、不再追加，职务按全称比较（「副董事长」≠「董事长」），不同的标待核实；分不清写法的（如「網谷 憲晴」「张三 监事」）保留原文、不追加、标待核实；电话固定 `PLAINTIFF_PHONE`；信用代码 / 负责人 / 住址取原告信息表（见下「原告信息表」）
- 合同类型（审批表「合同类型」）切换措辞：买卖合同「安装」→「供货」、「安装价格」→「产品价格」
- 台数：「约定原告负责安装 N 台」取合同台数（`elevator_qty_contract`），「N 台均于……验收合格」取验收报告台数（`elevator_qty`，代码计数：文字版报告按不同设备代码、取不到按报告编号；扫描报告按首页，见下「验收日期」）。合同与报告不一致时，`contract_scan` 节点补读合同设备清单、数 VGE 型号（家用电梯，无需验收报告，`services/equipment_list.py`；OCR 的 Markdown / HTML 表格与文字版合同空格 / 制表符对齐的清单都按表头「型号」「台数 / 数量」两列计数，某行对不上列时不计数、交律师，#112）：报告 = 合同 − VGE → 继续并提醒家用电梯；否则 `qty_check` 节点暂停，提醒律师核对报告是否齐全 / 有无补充协议 / 是否口头取消部分电梯，由律师定台数
- 签约日期：合同盖章页日期（盖章处写成「2024-05-24」的也算）；盖章页没写日期时取封面写到年月日的「签订日期」（只写到年月的「合同订立时间」不取）；扫描合同未识别时暂取审批表「签约时间」
- 被告名称：以合同盖章页「甲方 / 买方 / 需方 / 发包方」（`contract_party_a`）为准，审批表「合同买方名称」只在合同甲方读不到时用（律师反馈：审批表有时多写括号备注；不一致标待核实）。合同当事人只取合同，src 指向验收报告 / 审批表的 `contract_party_a/b` 由 `apply_rule_guards` 清空；派生的被告 / 原告名称出处开头沿用合同字段的「《合同文件名》第N页」并带页码（`derived_fields._with_cite`，#113），审核页能看到出自哪份合同，回原文核对来源也优先查该合同
- 被告住址 / 法定代表人：一律用工商登记信息（企查查、爱企查、启信宝），审批表地址不用（`extraction.apply_rule_guards` 清空）；审批表买方地址 / 合同盖章页甲方地址存为 `defendant_address_ref`，不写进起诉状，只在约定被告所在地（或未约定地点）管辖、工商住址还没填时推断法院，管辖句写明「【系统按被告地址「…」推断，待核实】」
- 联系人：只取审批表「联系人」，不取「甲方收款联系人」
- 验收日期：检验报告的批准 / 盖章日期，多份取最晚一批（文字版报告由代码在全部报告文件里取「批准」后的最晚日期，`extraction.apply_acceptance_date`，读不到才用 LLM 的值；一个案件常是每台电梯一份 PDF）。报告是扫描件（常为手机拍照）时，还有没读过的扫描报告 `report_ocr` 节点就逐页 OCR（上限 `AGENT_MAX_REPORT_OCR_PAGES`），按全部报告汇总（文本报告与扫描报告的批准日期取最晚，台数 = 文本报告计数 + 扫描报告首页计数；预算用尽或有页失败时出处注明「可能不全」，扫描计数的 OCR 待核实提示带到起诉状台数），用代码取「批准」后的日期、第一份「安装地点」，并按报告首页（「设备品种」栏）数台数——照片常裁掉报告编号，按编号去重会少数；同一设备代码 / 报告编号的首页只算一份（合并版与单份报告同时上传不重复计数，`acceptance_report.report_first_page_ids`；读不到标识的首页照算，律师新案例：中交一公局）；某份扫描报告数不出首页时退回按设备代码 / 报告编号计数，仍数不出则出处注明「可能不全」（`nodes._merge_acceptance_qty`、`services/acceptance_report.py`；OCR 输出的 markdown / HTML 表格先统一成纯文本）；仍读不到时退回审批表「政府验收时间」，标待核实
- 付款条款：原文（`payment_clause_text`）+ AI 归纳（`payment_clause_summary`，标「AI 归纳，待核实」）。起诉状只引用欠款对应的付款节点，条款号写到该项，照抄原文、加引号（确认单（五）第 3 题选 A）：`services/payment_nodes.py` 按编号拆节点（付款条款写成表格时按行拆：OCR 的 Markdown / HTML 表格，表头「累计」列按累计比例、「比例」列按本期比例，序号列作条款编号，其余单元格照抄；「合计 / 总计」汇总行、违约金行、没写支付的保函行不计；写成「第一期：……。第二期：……」的按分期标记拆，各期之间是句号也算），比例只认「支付……X%」（本期）与「支付至 / 付至……X%」（累计），保函百分比、「付到85%时」抵扣条件不计；「已付 + 欠款」占合同总价的比例对上某个累计节点时，引用已付比例到该比例之间的节点（`payment_cite_location`「第7.6条、第7.8条」，一级编号挂条款位置「第二十八章第1项、第2项」；`payment_cite_text`，去掉「验收款：」这类小标题，待核实）；节点拆不出、对不上时退回原条款位置 + AI 归纳句（没有归纳时写原文）；退回条款位置时，付款条款原文的出处写得更细（位置「第4条」、原文出自「第4.2条」）用更细的（`derived_fields._refined_payment_location`，#127）
- 支付至比例（`payable_ratio`）：先用「已付 + 欠款」占合同总价的比例匹配付款节点累计比例（律师反馈：如付至 95%），对上即取该比例、`retention` 节点不再暂停；都对不上（如算出 85%、节点为 5%-10%-70%-95%-100%）留【待补充】，出处与校验面板（`payment_progress`，琥珀色）提醒律师：可能调过价、实际台数与合同不同或质保金到期时间不统一，请手动核对；节点拆不出时按质保金规则（见下）
- 诉请金额（`claim_amount`，写入诉请第 1 项、利息基数和「尚欠…¥X元」句；审批表「未付款金额」`unpaid_amount` 照原值保留，金额勾稽不变）默认 = 审批表「未付款金额」。质保期未届满只诉已到期部分（确认单（六）第 1 题选 A，#138，`derived_fields.claim_amount_value`）：支付至比例 < 100% 且「合同总价 × 比例 − 已付」少于未付款时取该值；比例没定或没对上节点、审批表未付质保金 > 0 且推算质保期（最晚验收合格日 + 质保期，只认自验收起算）尚未届满时，取「未付款 − 未付质保金」，付款节点匹配也按扣除后的金额算；两种情况都标待核实、出处写明算式与未到期不诉的金额；律师选定支付至 100%、质保期读不到或不自验收起算时仍按未付款全额；律师改过诉请金额以律师为准。旧版 KA 审批表（合同类型「买卖附带安装合同」）一张表同时列买卖、安装两份合同：按本案合同文件名 / 标题（供货 / 买卖 / 设备 / 采购 → 买卖，安装 → 安装）取对应一栏的合同总额 / 已付 / 未付 / 未付质保金，合同类型改为本案那一种；判断不了时不动（`extraction.apply_dual_contract_amounts`，律师新案例：徐州九里苏宁）。质保金：合同有质保金时 `retention` 节点暂停，附质保金条款原文与审批表未付质保金，按分期比例给出选项（如 5% → 100% / 95%；满一年 2%、满二年 3% → 100% / 97% / 95%），律师选定「支付至 X% 合同款」；条款写的只是乙方另开银行质保保函（须正向写明「乙方……开具 / 提供……保函」，且无否定保函、无「保函后支付」、无「质保金」/ 预留 / 扣留 / 返还等现金质保写法，`derived_fields.retention_is_guarantee`；拿不准仍问律师）时不暂停，按支付至 100%（待核实）
- 移交：合同约定移交（甲方指定的）物业 / 物业单位的写「已全部移交物业」，否则写「已全部移交被告」（确认单（五）第 6 题，`handover_clause_text` / 付款条款）；合同付款条件含「结算」才加「并办理结算」（`handover_text`）
- 应付金额：「被告应按合同约定支付至X%合同款¥…元」写出金额 = 已付 + 欠款（`payable_amount`，确认单（五）第 5 题），支付至的比例 × 合同总价与之不等时标待核实
- 质保期到期句：欠款含质保金（审批表未付质保金 > 0）且质保期已届满时，在移交句后写「，质保期已于X年X月X日到期」（`warranty_expiry_sentence`，可选占位符），到期日 = 最晚验收合格日 + 质保期，标待核实；质保期不自验收起算、读不到或尚未届满时不写，出处说明原因（确认单（五）第 7 题）
- 战略 / 框架合同：文件名或标题含「战略合同 / 战略合作 / 战略协议 / 框架合同 / 框架协议」的单独归为「战略合同」类（先于「补充协议」判断：《战略协议补充协议七》是战略合同的补充，仲裁条款在里面）；扫描件按需 OCR 另给 `AGENT_MAX_STRATEGIC_OCR_PAGES` 页，不被主合同用完的 50 页挤掉（律师反馈：徐州苏宁的争议条款在战略合同里），不当主合同；按需 OCR 找条款时排在主合同之后（`nodes._clause_ocr_targets`），且只补缺失的付款 / 违约 / 争议 / 质保条款（`nodes._STRATEGIC_CLAUSE_KEYS`），不取当事人、签约日期、合同名称、台数、工程地点等本案字段，也不以它的签章页为准；主合同争议条款只写「争议的解决……按战略合同执行」、本身没约定仲裁 / 法院时（`extraction.refers_to_strategic`），清空条款内容、保留主合同条款位置，再去战略合同里读（文字版不 OCR），读到后位置写「第X条及战略合同第Y条」，起诉状为「依据案涉合同第X条及战略合同第Y条约定，……」；取自战略合同的当事人、日期等本案字段由 `extraction.apply_strategic_guards` 清空；模型漏抽「争议……按战略合同执行」（常写在「合同的组成及解释」列表里）时由代码从主合同原文补上这句与条款位置（OCR 丢了列表编号时按同一缩进的列表项数，标「推算，待核实」，`extraction.apply_strategic_dispute_ref`），这句也算按需 OCR 的「争议条款已找到」；没读到战略合同的争议条款（未上传或未识别）时文书类型、管辖法院、管辖句、致送留【待补充】，出处与校验面板（`strategic_dispute`，琥珀色）提醒上传战略合同，不按「未约定」套被告住所地法院；争议条款没读到时文书类型暂按民事起诉状并标待核实，不写「争议条款约定诉讼」（#126）
- 补充协议：文件名含「补充协议 / 补协 / 修改单 / 变更协议」（或正文开头有「补充协议」）的材料单独归为「补充协议」类，不当合同 OCR（`file_parser._TYPE_KEYWORDS`）；有补充协议时「合同总价为¥…」写合同正文原价（`contract_total_in_contract` → `contract_total_stated`），其后加「后双方签订补充协议，确认合同总价变更为¥<审批表合同总额>元。」（`supplement_sentence`，可选占位符），一律标待核实交律师确认（确认单（五）第 8 题：补充协议可能改单价、数量、规格、税率）
- 诉请「剩余合同款 / 到期合同款」：已付 + 欠款 = 合同总价写「剩余合同款」，否则写「到期合同款」；已付 + 欠款大于总价（可能调过价）或金额缺失时标待核实（`debt_term`，确认单（五）第 9 题）
- 逾期利息：合同有甲方逾期付款利率 → 用约定（待核实）；否则「全国银行间同业拆借中心公布的一年期贷款市场报价利率」，一律自起诉之日起算，基数为欠款金额
- 违约金：合同甲方逾期付款条款写的是「违约金」（`breach_clause_text` / `breach_interest_rate_text` 含「违约金」）→ 诉请与事实理由写「违约金」（`interest_term`），并在违约段落前引用条款「依据合同第X条约定，<原文>。」（`breach_clause_sentence`，待核实；条款号只写最细一级，如「第十条第10.2条」→「第10.2条」，原文中的甲方 / 乙方换成被告 / 原告，确认单（五）第 13 题）；否则写「逾期付款利息」、不引用。安装 / 买卖合同一样。违约条款里同时有乙方延迟 / 未按期交货、完工的违约金时，只取甲方逾期付款那几句（原条款留 `raw_value`，出处注明），抽出的违约利率只出现在去掉的乙方句子里的一并去掉；甲方句子另写了利率时不套用 LPR，交律师填写（`extraction._guard_breach_clause`，#124）。约定违约金却没有按日 / 月 / 年计算的标准（须同时有比率或金额与计算周期，周期含「每日 / 每逾期一日 / 按日 / 日万分之 / 100元/日」等写法；「逾期超过30日」只是触发期限；「一次性结清」等付款方式字样不改变按期计算）时，按固定金额 / 一次性比例处理（律师确认单（四）第 1 题）：诉请与事实理由的「（以¥…为基数……计至实际付清之日止）」整段换成违约金金额（`penalty_amount`，`complaint_renderer` 替换模板），条款只有一个金额的照抄，写「合同总价 / 欠款的 X%」的按合同总价或未付金额算出，一律标待核实；含上限 / 下限 / 累计等附加条件、出现多个计算标准（按「基数 + 比例」比较，如「欠款的5%」与「合同总价的5%」算两档）或多个金额（分档）、比例与金额混用、比例基数识别不了、缺基数时不自动计算，留【待补充】；「每日100元」这类按期计付的固定金额不算一次性金额；律师改过计算标准则不切换。按合同费率计付且条款约定了上限（「最高不超过安装费总额的10%」）时，诉请与事实理由括号末尾照写上限（`penalty_cap`，可选占位符，待核实；金额千分位逗号不断句，写到哪分不清时留【待补充】）

## 原告信息表（全所共用底表，管理员维护）

- 原告的统一社会信用代码、法定代表人 / 负责人、住所地不在案件材料里，取自律师维护的《原告信息表》（Excel：原告名称 | 统一社会信用代码 | 住所地 | 法定代表人\负责人 | 联系方式）。它是全所共用的底表，**不是**每个案件上传的材料。
- 前端页头「原告信息表」入口：所有人可查看、下载当前 Excel；**只有管理员**（输入服务器 `ADMIN_TOKEN` 口令）能上传新版本或恢复历史版本。口令经请求头 `X-Admin-Token`（encodeURIComponent 编码）传给后端比对；未配置 `ADMIN_TOKEN` 时任何人都不能更新。保存 / 恢复时把当前登录账号（`request.state.user`）记为该版本的上传人（`uploaded_by`），页面与历史列表显示；未开启登录（本地开发）则为空。只想让某位律师上传：把口令只告诉这位律师。
- 更新分两步：`POST /api/branches/preview` 解析 + 校验 + 与当前版本比对（不保存）→ 管理员确认后 `POST /api/branches` 保存。完全相同的重复行自动合并并提醒；同名但内容不同 / 缺名称阻止保存；信用代码校验位不符、缺负责人或住址只提醒。
- 存储：`BRANCH_INFO_PATH`（默认 `backend/data/branch_info.json`），每次更新前旧版本存入 `BRANCH_HISTORY_DIR`，可 `POST /api/branches/restore` 回退。数据留在部署服务器，不进 git。
- 名称比对前去空白、半角括号转全角（律师表里部分行写「日立电梯(中国)」）。查询按文件修改时间缓存，上传后立即生效、无需重启。
- 字段来源写「《原告信息表》YYYY-MM-DD 版」；超过 `BRANCH_TABLE_STALE_DAYS`（90 天）未更新或尚未上传时，上传页提醒负责人可能已变更。
