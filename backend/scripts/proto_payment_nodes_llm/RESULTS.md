# 原型结论（2026-11-21，全部虚构语料，DeepSeek 线上主模型）

问题：付款节点改成「LLM 给结构 + 代码核与版式无关的不变量」，能否少写正则、又不放过错拆？

结论：在这批虚构语料上能。
- **错拆**：LLM 三轮独立调用都是 0；正则有 2 条（`虚构首批即停案J` 50→100 被拆成一个 0→100；`留出_质保金写在前面` 拆成 5→55→100）。
- **覆盖**：没为之写过规则的 23 条变体里，LLM 认对 18 条、正确放弃 5 条；正则认对 5 条、放弃 12 条、错拆 1 条。
- **不变量拦截**：把 LLM 的正确输出故意改错，约 1000 次篡改 0 漏过（比例看错、片段改字、本期 / 累计弄反、漏节点、编号错配、排除项丢失）。
- **代价**：同一项里拆出两期、共用一个编号的（如「6.1 ……定金……，……付至80%」）现在放弃交律师；每案多一次文字 LLM 调用。

注意：
- 不变量是看着这批语料调了四轮的；heldout2 写于第二轮之后，严格说也不算完全干净的留出集。heldout / heldout2 的标注是原型作者按字面手标的，未经律师确认。
- 只验证了「拆节点」这一步；一体化合同选段、引用写法（第3.1.4条）、律师措辞不在范围内。
- 还没在服务器上的真实案卷（真实 OCR 文本）上跑过，这是能否落地的关键一步。

复现：`python scripts/proto_payment_nodes_llm/run.py --cache <目录>`（需 DEEPSEEK_API_KEY）；`mutate.py --cache <目录>` 跑篡改测试。
